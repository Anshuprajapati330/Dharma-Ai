# Dharma-AI

Dharma-AI is an interview-ready AI assistant project that combines a Streamlit frontend, a FastAPI backend, SQLite persistence, and a vector database for retrieval-based responses.

## What makes it interview-ready

- Backend API with authentication and chat persistence
- Database-backed user and chat storage using SQLAlchemy
- Retrieval-augmented responses using ChromaDB and embeddings
- Container and cloud deployment support with Docker and Render
- Test coverage for the backend API

## Project structure

- chatbot.py: Streamlit frontend experience
- backend/main.py: FastAPI backend endpoints
- backend/models.py: SQLAlchemy database models
- dharma_ai.py: response generation with retrieval and Groq
- load_data.py: embedding ingestion for knowledge data
- tests/test_backend.py: backend regression tests

## Run locally

1. Install dependencies:

```bash
python -m pip install -r requirements.txt
```

2. Create a `.env` file:

```env
GROQ_API_KEY=your_api_key_here
API_BASE_URL=http://127.0.0.1:8000
DATABASE_URL=sqlite:///./dharma.db
```

3. Start the backend API:

```bash
uvicorn backend.main:app --reload
```

4. Start the Streamlit UI:

```bash
streamlit run chatbot.py
```

### Windows PowerShell

Open two PowerShell terminals in the project directory and run:

```powershell
.\.venv\Scripts\python.exe -m uvicorn backend.main:app --host 127.0.0.1 --port 8000
```

```powershell
.\.venv\Scripts\python.exe -m streamlit run chatbot.py --server.port 8501
```

The frontend defers its local API health check until login or signup, so a
backend that is still starting does not block the initial page render.
The knowledge-base embedding model also warms up in the background from the
initial page load, so its first-time download and load can happen while you are
on the login screen rather than after you send your first message.

## Runtime behavior

- `GROQ_MODEL` selects the model used for responses and translations. The
  application does not silently switch to another model when it fails.
- Hindi and English Listen actions use language-matched Edge TTS voices:
  `hi-IN-SwaraNeural` and `en-US-AriaNeural`. Speech text is sent in a POST
  request body, and successful audio is cached with bounded memory use; failed
  synthesis is not cached.
- Backend logs record retrieval, prompt, model-generation, translation, and
  TTS timing; these timing records contain durations and model/voice
  identifiers, not message text.
- Chat generation retrieves knowledge-base context for each turn and sends
  recent user and assistant turns with their original roles. Contextual
  follow-ups use both sources to answer directly rather than restart prior
  guidance. Responses avoid unsupported citations and keep the Gita,
  Mahabharata, and Western ethics perspectives conditional on relevant retrieved
  evidence.

## Deployment

- Docker: build with `docker build -t dharma-ai .`
- Render: the included `render.yaml` defines separate API and Streamlit services.
- Configure a managed PostgreSQL database and set its connection string as the API service's `DATABASE_URL`.
- Set `GROQ_API_KEY` on the API service. `JWT_SECRET_KEY` is generated by Render automatically.
- Update `CORS_ORIGINS` if you use a custom frontend domain, then deploy the blueprint from the repository.
- Set `API_BASE_URL` on the frontend service to the public API URL.

The API refuses to start without `JWT_SECRET_KEY`, and production should never use the local SQLite database for persistent user data.
